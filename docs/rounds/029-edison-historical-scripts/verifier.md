## Findings

- [BLOCKER] `data/custom-cards/c600000003.lua` (and its copy `dist/scripts/c600000003.lua`) — the script is not "original, not a copy or an adaptation of any Project Ignis CardScripts file". Compared with `official/c16226786.lua` at the pinned revision, 38 of its 49 code lines are identical after normalisation (sequence ratio 0.69). It has the same effect definitions in the same order, the same function names (`s.destg`, `s.desop`, `s.thcon`, `s.thfilter`, `s.thtg`, `s.thop`), the same `Duel.Hint`, `SelectTarget` and `SetOperationInfo` lines, and the same `TYPE_FLIP` / `IsAbleToHand` filter. Its edits are the ones the record needs (drop the self-exclusion, select on resolution). Several of these names are Ignis conventions, and a trivial card script leaves little room for variation, so I cannot prove copying. But the file reads as a modification of the AGPL script, and the header, all three `authorship` notes, `dist/README.md`, `docs/errata.md`, `docs/roadmap.md` and the `custom-card.authorship-not-original` rule's message all assert the opposite. The brief says: if a derived script's distribution under MIT "cannot [be established], or it is unclear, **stop before committing any derived script** and report … that is an owner decision." Ignis's `COPYING` is the AGPL-3.0 text and its README grants "version 3 … or (at your option) any later version", so the Builder's licence reading is right. Failure path: merging distributes an arguably AGPL-derived file in an MIT repository, labelled as original, and the validator cannot catch it because it only checks that the field says `original`. The fix is an owner decision, or a rewrite by someone who has not read the Ignis script, or holding this card back (the Builder suggests the last in Open question 1; the other two cards are independent of it).

## Verdict

The engineering is sound. The generator, validator rules, stale-output guard, `dist/` layout, Edison list swap and engine harness all reproduce on my machine. The 45 engine tests pass locally and in CI at the exact head, and for all three cards the engine tests fail as soon as the script behaves like the modern card, which I checked myself and which matches the Builder's red CI runs. GOAT and Tengu are untouched, `validate` shows 0 errors, and the three period texts match Yugipedia's first printings. I do not think this round should merge as it stands, because of the licence question. The Night Assailant script is a close adaptation of Project Ignis's AGPL-3.0-or-later script (about 78% of its lines match) that is labelled, in the code, the records, the docs and a validator rule, as original work written without it, and the brief says to stop for an owner decision in exactly this case. The Vehicroid script is a weaker version of the same concern. The rest is minor: the warning count falls by 1 rather than 3 for a good reason, and one existing test now allows more difference than the change needs. I am confident in the measurements and the engine results. I am not confident about the legal reading, and it is not mine to make. The cheapest way forward is for the owner to hold Night Assailant back, or approve a clean rewrite, and to look at Stealth Union alongside it. Metalzoa looks clean.
